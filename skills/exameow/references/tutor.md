# 连续辅导：一题一题陪学

目标：用户不用自己找题、不用手动翻页。你负责出题 / 选题、等回答、判分、讲解、讨论，
用户说「继续」再切下一题。

## 开场先对齐

1. `app_status` 看：
   - `ai_configured`：没配模型就只能用已有题库，不能生成新题。
   - `bank_count` / `active_session`：有没有现成题库或未完成的练习。
2. 问用户（一次问清，别反复打断）：
   - 练哪一科 / 哪个题库；
   - 题量或时长；
   - 题型偏好（选择 / 判断 / 填空 / 简答）；
   - 想要「先做题后讲」还是「答错才讲」。
3. 没有题库：
   - 有材料 → `generate_exam` + `save_to_bank:true`；
   - 没材料 → 让用户给文档或主题，或者用已有题库。

## 主循环（严格遵守顺序）

```
start_practice
   ↓
展示第 N 题（只给 stem + options）
   ↓
等用户回答 / 提问
   ↓
submit_answer
   ↓
判分 + 讲解 + 回答追问
   ↓
用户说继续 → next_question
   ↓
（回到展示第 N+1 题）
   ↓
最后一题讨论完 → finish_practice
```

### 1. 展示题目

只展示：

- 题号 / 总数（例如「第 3 / 20 题」）；
- 题型与难度（如果返回里有）；
- `stem`；
- `options`（原样，带 A. B. C.）；
- 图片提示（`media` 非空时告诉用户「这题有图片，见 App 界面」）。

**不要**展示 `answer`、`analysis`、`correct_answer`——当前题本来也拿不到答案。

### 2. 等回答

- 不要自问自答，不要替用户选。
- 用户说「不会」：给**一级提示**（考哪个概念 / 排除一个明显错误项），不要直接给答案。
  用户再要提示，再给一级；仍不会可以让他猜或跳过。
- 用户问概念题：先解释概念，再请他回到原题作答。解释里不要出现当前题的正确选项。
- 用户一次发多个答案：按当前题解析，多余的留到后面。

### 3. 提交

```bash
exameow call submit_answer --json '{"answer":"B"}'
```

- 简答题：先用 `use_ai_judge:true`；如果模型没配，让用户自评或改用 `judge_answer`。
- 填空：保留用户原文，不要擅自改写。
- 返回里拿 `is_correct`、`correct_answer`、`analysis`。

### 4. 判分与讲解

回答结构建议：

1. **结论**：对 / 错 / 部分对。
2. **为什么**：结合 `analysis`，用用户能懂的语言；必要时补背景。
3. **错因**（答错时）：概念混淆 / 计算失误 / 审题 / 选项干扰。
4. **记忆点**：一句话总结，方便下次遇到同类题。
5. **追问入口**：「还有哪里不清楚？懂了就说『下一题』。」

- 用户要求更细 / 联网 → `explain_question`：

  ```bash
  exameow call explain_question --json '{
    "stem":"...","reference_answer":"...","analysis":"...",
    "language":"Chinese","use_search":true
  }'
  ```

- 用户问的是**别的题**：用 `answer_question` / `explain_question` 单独处理，不要影响当前
  session 的题号。

### 5. 下一题

只在以下情况调用 `next_question`：

- 用户明确说「下一题 / 继续 / 懂了 / 跳过」；
- 当前题已经讲解并回答完追问；
- 或者用户要求暂停后重新开始。

返回 `at_end:true` → 不再调用，进入总结。

### 6. 总结

`finish_practice` 后给：

- 正确率、答对 / 答错 / 未答数量、用时；
- 2–3 个薄弱点（从错题的 `analysis` / 题干归纳）；
- 建议：再来一轮错题 `mode:"wrong"`，或针对薄弱点生成新题。

## 不剧透规则（重要）

| 场景 | 可以做 | 不可以做 |
| --- | --- | --- |
| 用户还没作答 | 给概念提示、排除项 | 说「答案是 B」、贴 `analysis` |
| 用户答错 | 讲正确答案 + 原因 | 嘲讽 / 只给答案不解释 |
| 用户答对 | 确认 + 补一个延伸点 | 强行再讲一遍 |
| 用户问「直接告诉我」 | 先确认是否真的要跳过思考，再给 | 默认直接给 |

`get_bank` 会返回答案；它是**备课资料**。不要把整库答案一次性贴给用户。

## 节奏与体验

- 一题一条消息，别把 10 道题和答案一次性倒出来。
- 每题控制篇幅：讲解 3–6 句，追问再展开。
- 用户长时间不回复：不要催；可以问「需要提示吗？」
- 用户说「今天只练 5 题」：练完 5 题就 `finish_practice`，不要自动续。
- 用户中途换科目：先 `finish_practice`（或确认放弃），再开新 session。
- 移动端 / 小屏：选项分行，避免长表格。

## 常见用户话术 → 动作

| 用户说 | 你做什么 |
| --- | --- |
| 「开始吧 / 出题」 | 确认题库与题量 → `start_practice` |
| 「提示一下」 | 给一级提示，不提交 |
| 「不会，直接讲」 | 可先提交空答案或让用户猜；然后讲 |
| 「为什么选 C」 | 用 `analysis` 解释，必要时 `explain_question` |
| 「下一题」 | `next_question` |
| 「刚才那题再讲一遍」 | 用上一题的 `correct_answer` / `analysis` 复述 |
| 「只练错题」 | `finish_practice` → `start_practice {mode:"wrong"}` |
| 「今天到这」 | `finish_practice` + 总结 |
| 「把这些题发给我」 | `export_questions`（XLSX 保留图片） |

## 失败处理

- `app_not_connected` / `app_suspended`：请用户把 Exameow 窗口带到前台；重试一次。
- `ai_not_configured`：转成「用已有题库练习」或让用户去设置里配模型。
- `no_session`：重新 `start_practice`。
- `no_questions`：该题库为空 / 没有错题；换题库或先生成题。
- 超时：缩小 `count`，或把长文档拆批。
